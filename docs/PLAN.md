# План разработки «Weather Tree»

**Версия плана:** 0.1 · **Дата:** 13.11.2026 · **Статус:** M0 выполнено

---

## 1. Цель

Одностраничное веб-приложение: экран погоды с текущим временем и анимированным
пиксельным деревом, которое выглядит правдоподобно для *сейчас*, *здесь* и *такой погоды*.

Главное требование — не «4 сезона × 3 погоды» на выбор, а **непрерывная модель**:
дерево меняется по фенологической кривой года, освещение — по астрономическому
положению солнца, а погода накладывается как слой поверх (ветер, осадки, снег на ветках,
влага, туман, гроза).

### Критерии приёмки (из ТЗ)

| Сценарий | Ожидаемый кадр |
|---|---|
| 12:00, 9 июля, ясно, без ветра | Густая зелёная крона, высокое солнце, короткая тень, светлое небо, лёгкая рябь листвы |
| 14 января, 19:15, метель | Голые ветки, снег на ветках и земле, синие сумерки/ночь, снежная крупа с сильным боковым сносом, качание ствола, подсветка от «фонаря», звёзд не видно |

Оба кадра должны воспроизводиться детерминированно (одинаковый ввод → одинаковый вывод).

## 2. Рамки и принципы

1. **Serverless.** Только статика на GitHub Pages. Никакого бэкенда, ключей и прокси.
2. **Zero-dependency.** Ноль npm-пакетов в рантайме и в сборке. Сборки нет вообще:
   нативные ES-модули, `<script type="module">`.
3. **Всё процедурно.** Ни одного бинарного ассета: дерево, облака, тайлы, шрифт-цифры
   рисуются кодом. Репозиторий остаётся крошечным, а состояния — параметризуемыми.
4. **Пиксельная честность.** Логическое разрешение **320×180**, апскейл целым множителем,
   `image-rendering: pixelated`. Никакого сглаживания, никаких полупиксельных градиентов —
   градиенты только через ограниченную палитру и ordered dithering (Bayer 4×4).
5. **Детерминизм.** Весь визуал — чистая функция `WorldState`. Сид генерации ствола —
   хеш от координат, поэтому дерево «одно и то же» между перезагрузками, но у каждого
   города своё.
6. **Сеть — только по расписанию.** Погода запрашивается раз в 10 минут и при
   возврате фокуса на вкладку; анимационный цикл в сеть не ходит никогда.
7. **Деградация, а не падение.** Нет сети / отказ геолокации / 429 от API — показываем
   последний кэш из `localStorage`, иначе «демо-режим» с явной плашкой.

### Вне рамок

Бэкенд, аккаунты, история погоды, прогноз на неделю, WebGL, звук, мобильное приложение,
локализация сверх ru/en, SSR.

## 3. Архитектура

```
┌──────────────┐   fetch    ┌────────────────┐   normalize   ┌────────────┐
│ Open-Meteo   │ ─────────► │ api/openMeteo  │ ────────────► │ WorldState │
│ forecast +   │            │ geocoding      │               │  (модель)  │
│ geocoding    │            └────────────────┘               └─────┬──────┘
└──────────────┘                                                  │ derive
                                                                  ▼
┌──────────┐   rAF    ┌───────────────────────────────────────────────────┐
│  HUD     │ ◄─────── │  scene.render(state, t)  → 320×180 buffer          │
│ (DOM)    │          │  sky · celestial · clouds · hills · tree ·        │
└──────────┘          │  weather · foreground                             │
                      └───────────────────────┬───────────────────────────┘
                                              │ upscale ×N
                                              ▼
                                         <canvas>
```

**Поток данных:** `Open-Meteo JSON → Station → WorldState → SceneState → пиксельный буфер`.
Каждый шаг — чистая функция, покрытая тестом.

### 3.1 Провайдеры погоды

`api/weather.js` держит цепочку из двух независимых keyless-API и отдаёт единый `Station`:

| Провайдер | Данные | Зачем |
|---|---|---|
| `api.open-meteo.com` | WMO-код, порывы, облачность, восход/закат, точное смещение пояса | точнее и богаче, основной |
| `wttr.in` | WWO-код (маппится в WMO), температура, ветер, восход/закат | фолбэк: `open-meteo` блокируется в РФ и части сетей |

Правила:

* порядок — сначала провайдер, который сработал в прошлый раз (`localStorage`);
* рабочий провайдер запоминается, чтобы не платить таймаутом при каждом обновлении;
* таймауты короткие (6–8 с), повторов нет: лучше быстрый фолбэк, чем долгое ожидание;
* если не ответил никто — 45 с и ещё до 5 попыток, затем только плашка `нет данных`;
* кэш и `WorldState` не знают, кто ответил; провайдер виден только в подсказке плашки источника.

## 4. Модель мира

`WorldState` — единственный источник правды для рендера.

```js
{
  now: { iso, tz, offsetMinutes, dayOfYear, hour, minute },
  place: { lat, lon, name, country },
  weather: { code, tempC, feelsC, windKmh, windDirDeg, gustKmh,
             cloudPct, precipMm, humidity, visibilityKm, isDay },
  derived: {
    hemisphere: 'N' | 'S',
    seasonPhase: 0..1,        // 0 = глубокая зима, 0.5 = лето
    daylight: 'night'|'astro'|'nautical'|'civil'|'golden'|'day',
    sun: { altitudeDeg, azimuthDeg, up: bool },
    moon: { altitudeDeg, phase 0..1, up: bool },
    precip: { type: 'none'|'rain'|'drizzle'|'snow'|'grains'|'hail',
              intensity 0..1, isFrozen: bool },
    wind: { vector, gust 0..1, swayAmp 0..1 },
    ground: { snowDepth 0..1, wetness 0..1, frost 0..1, litter 0..1 },
    air: { fog 0..1, haze 0..1, storm 0..1, lightLevel 0..1 }
  }
}
```

### 4.1 Фенология (время года)

Не 4 дискретных сезона, а кривая по дню года, сдвинутая полушарием и смягчённая
континентальностью (учитываем широту: на экваторе сезонности почти нет, ближе к полюсам — резче).

| `seasonPhase` | Состояние кроны |
|---|---|
| 0.00–0.12 | глубокая зима: только скелет, снег на ветвях |
| 0.12–0.28 | конец зимы: набухшие почки, самый тёмный ствол |
| 0.28–0.42 | распускание: молодая светло-зелёная листва, цветение (для цветущих пород) |
| 0.42–0.68 | полная крона, насыщенный зелёный |
| 0.68–0.82 | конец лета: лёгкое пожелтение, пыль на листьях |
| 0.82–0.94 | осень: жёлтый → оранжевый → багровый, листопад |
| 0.94–1.00 | голые ветки, листовой опад на земле |

Погодные поправки: затяжная жара ускоряет пожелтение, ранние заморозки — сброс листвы,
ветер ускоряет листопад.

### 4.2 Светила и фаза суток

Высота и азимут солнца считаются астрономически (упрощённый алгоритм NOAA) из
координат и времени — значит, для Мурманска зимой будет полярная ночь, а для Сиднея
январь — это лето. Фаза суток определяется по высоте солнца:

| Высота солнца | Фаза | Что видно |
|---|---|---|
| < −18° | ночь | звёзды, луна, тёмно-синее небо |
| −18…−12° | астрономические сумерки | первые звёзды |
| −12…−6° | навигационные сумерки | глубокий синий, силуэт дерева |
| −6…−0.8° | гражданские сумерки | оранжево-розовая полоса у горизонта |
| −0.8…+6° | golden hour | тёплый боковой свет, длинные тени |
| > +6° | день | палитра по сезону и облачности |

Луна: фаза по синодическому циклу, высота — по той же астрономии, свечение ночью
при ясном небе.

### 4.3 Погода → физика сцены

Код WMO (`weather_code`) разворачивается в набор параметров. Полная таблица —
[docs/WEATHER-MAPPING.md](WEATHER-MAPPING.md). Ключевые правила:

* `precipType` = `snow`, если осадки есть и `temp ≤ +1.5 °C` (либо `code` из снежного диапазона 71–77, 85–86);
* `snowDepth` растёт при снегопаде и тает при `temp > 0` и солнце (медленно, чтобы состояние не дёргалось);
* `wetness` растёт от дождя и сохнет за ~20 минут без осадков;
* `swayAmp` = f(`windKmh`, `gustKmh`) с порогом: до 8 км/ч дерево почти неподвижно;
* `fog` — из `visibilityKm` (Open-Meteo отдаёт его отдельно) и кода 45/48;
* `storm` — коды 95–99: вспышки молний, резкий ветер, тёмно-фиолетовая палитра.

## 5. Рендер

### 5.1 Слои (снизу вверх)

| # | Слой | Перерисовка |
|---|---|---|
| 1 | Небо: полосы палитры + Bayer-dither на стыках | при смене фазы/погоды (каждые ~30 с) |
| 2 | Звёзды (яркость по свету), Млечный путь при ясной ночи | по состоянию неба |
| 3 | Солнце/луна, гало, лунная дорожка | каждый кадр (позиция) |
| 4 | Облака: 3 слоя, параллакс, скорость от ветра, плотность от `cloudPct` | каждый кадр |
| 5 | Дальний план: холмы, снеговая линия | по сезону |
| 6 | Дерево: скелет (кэш) → листва → снег/наледь → капли → тень на земле | скелет — кэш; листва — каждый кадр |
| 7 | Погодные частицы: дождь/снег/крупа, молнии, туман | каждый кадр |
| 8 | Передний план: трава, сугробы, лужи, опад | по состоянию земли |
| 9 | Пост-обработка: ночной тинт, виньетка, «мокрое стекло» при ливне | при смене состояния |

### 5.2 Техника пиксельного арта

* Единый буфер `Uint32Array` 320×180 в `ImageData`, палитра ≤ 32 цветов на сцену.
* Все фигуры — целочисленные: линии Брезенхема, эллипсы без антиалиасинга,
  dithering 4×4 Bayer для неба и тумана.
* Дерево параметризовано: `trunkH`, `spread`, `branchAngle`, `leafDensity`,
  `leafPalette`, `snowLoad`, `bend`. Один и тот же код даёт и юную яблоню, и старый дуб.
* Ветер — глобальное поле смещения: `bend(x, y, t)` через сумму двух синусов
  (низкочастотный порыв + высокочастотная дрожь листвы). Ствол гнётся по квадрату высоты,
  листва — с индивидуальной задержкой, чтобы движение шло волной.
* Кэш: скелет и фон рисуются в `OffscreenCanvas` и переиспользуются, пока не изменился
  `WorldState`. Это держит бюджет кадра < 4 мс даже на слабых устройствах.

### 5.3 Анимация

* Один `requestAnimationFrame`, фиксированный шаг симуляции 1/30 с, рендер с `dt`-сглаживанием.
* Частицы: пул объектов (дождь ~220, снег ~160), переиспользование без аллокаций в кадре.
* Разгоняется по реальному ветру: скорость падения + горизонтальный снос + вращение снежинок.
* `prefers-reduced-motion`: анимация ветра и частиц отключается (или сильно замедляется),
  остаётся статичный, но корректный кадр.

### 5.4 HUD

DOM поверх canvas (а не пиксельный шрифт в буфере) — так текст остаётся чётким и доступным:

* крупные часы `HH:MM` + секунды, дата;
* температура, «ощущается как», описание по WMO-коду, ветер (сила/направление), влажность;
* точка: город/координаты, «обновлено N мин назад»;
* индикатор источника: `live` / `cache` / `demo`;
* кнопка выбора города и режим «проверить другую дату» (таймшифт для проверки сценариев).

## 7. Тестирование

| Уровень | Что проверяем | Инструмент |
|---|---|---|
| Unit | `season.js`, `weather.js`, `sun.js`, `palette.js` — граничные значения, полушария, полярный день | `node --test` |
| Golden-frame | 6–8 состояний: пиксельный буфер → хеш | `tools/snapshot.mjs` + `node --test` |
| Визуальное ревью | Полный год по месяцам, 24 часа, все WMO-группы | snapshot-галерея |
| Ручное | Телефон, офлайн, отказ геолокации, смена часового пояса | чеклист |

Чистые функции вынесены из DOM и canvas, поэтому тестируются в Node без браузера.

## 8. Риски и решения

| Риск | Вероятность | Решение |
|---|---|---|
| Open-Meteo меняет схему / лимиты | низкая | один адаптер `api/openMeteo.js`, кэш, graceful fallback в демо-режим |
| Провайдер недоступен в сети пользователя (РФ: Open-Meteo блокируется) | высокая | цепочка из двух независимых keyless-API + запоминание рабочего (M1.1) |
| Отказ геолокации у большинства | высокая | ручной выбор города как основной сценарий, IP-fallback, запоминание |
| Приватность координат | средняя | округление до 2 знаков (~1 км), никакой аналитики, только Open-Meteo |
| Производительность на слабых устройствах | средняя | 320×180, кэш статики, лимит частиц, авто-снижение при просадке fps |
| «Дёрганье» снега/влаги при колебаниях API | средняя | сглаживание состояний (EMA) и гистерезис |
| Расхождение «правдоподобно» vs «красиво» | высокая | калибровка по референсным фото, приоритет правдоподобия |
| Нет прав на включение Pages | низкая | проверено на M0; при отказе — деплой веткой `gh-pages` |
