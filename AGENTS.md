# Правила разработки в этом репозитории

## Что это

Статическое веб-приложение на GitHub Pages: погодный экран + процедурное пиксельное
дерево. Никакого бэкенда, сборки и npm-зависимостей. Подробности — [docs/PLAN.md](docs/PLAN.md).

## Жёсткие ограничения

1. **0 зависимостей.** Не добавлять пакеты в `package.json` (ни `dependencies`, ни
   `devDependencies`). Не добавлять бандлеры, транспиляторы, линтеры «на всякий случай».
   Если очень нужно — сначала обсудить, затем зафиксировать в PLAN.md.
2. **Только ES-модули браузера.** Код работает «как есть» через `file://`-совместимый
   статический сервер; никаких `import` без расширения `.js`, никакого CommonJS в `src/`.
3. **Никаких бинарных ассетов.** Ни PNG, ни шрифтов, ни иконок — всё рисуется кодом.
   Исключение: скриншоты в `docs/`.
4. **Никаких сетевых вызовов в анимационном цикле.** Погода — раз в 10 минут и при
   возврате фокуса; всё остальное время рендер живёт на `WorldState`.
5. **Никаких ключей API.** Open-Meteo работает без ключа; если появляется сервис,
   которому нужен ключ, — он не подходит.
6. **Только Canvas 2D.** Не WebGL, не сторонние движки.

## Пиксельная дисциплина

* Логическое разрешение сцены — `320×180` (`config.js: LOGICAL_W/H`). Менять только вместе
  с переработкой всех палитр и таймингов частиц.
* Координаты при рисовании — целые. `ctx.translate(0.5, 0.5)` и антиалиасинг запрещены.
* Палитра сцены ≤ 32 цветов, градиенты — только через Bayer 4×4 (`render/surface.js`).
* Апскейл — целым множителем, `image-rendering: pixelated`. Исключение: когда целый
  множитель равен 1× (узкий экран), сцена тянется дробно по ширине — `pixelated`
  не размывает, а иначе экран телефона выглядит пустым.

## Детерминизм

* Визуал — чистая функция `WorldState` (+ `t` для анимации).
* Все генераторы случайности принимают явный сид; глобального `Math.random()` в рендере нет.
* Golden-тесты ловят расхождения; если кадр изменился намеренно — обновляем эталон
  и описываем причину в коммите.

## Слои и ответственность

| Каталог | Можно | Нельзя |
|---|---|---|
| `src/api/` | fetch, кэш, таймауты | знать про canvas |
| `src/model/` | чистые функции, астрономия, фенология | трогать DOM |
| `src/render/` | canvas, буферы, палитры | fetch, `localStorage` |
| `src/ui/` | DOM, события | рисовать на canvas |
| `src/state/` | связывание, персист | знать про пиксели |

Правило: `model/` и `render/surface.js` импортируются в `node --test` без браузера —
если модуль тянет DOM, он лежит не там.

## Стиль кода

* 2 пробела, `;`, одинарные кавычки, `const` по умолчанию.
* Имена — английские, комментарии — русские и только там, где объясняют «почему».
* Файл — одна ответственность, до ~300 строк; больше — делить.
* JSDoc на экспортируемых функциях `model/` и `render/`: типы входов/выходов.
* Ошибки: не глотать, возвращать `{ok:false, reason}` из API-слоя.

## Git

* Ветка `main` — всегда деплоится. Работа — в ветках `feat/…`, `fix/…`, `docs/…`.
* Коммиты: `feat: …`, `fix: …`, `docs: …`, `refactor: …`, `test: …`, `chore: …`.
* Один коммит = одна логическая правка; сообщение объясняет «зачем».
* Перед пушем: `npm test` зелёный.

## Проверки перед PR

```bash
npm test                        # unit + golden-frame
npm start                       # ручная проверка в браузере
npm run snapshot                # рендер кадра в snapshots/out + замер времени
```

Чеклист глазами: 9 июля 12:00 ясно; 14 января 19:15 метель; ночь; полярная ночь;
осенний дождь; мобильный экран; офлайн после первой загрузки.

## Доступность

* `prefers-reduced-motion: reduce` — останавливает ветер и частицы (кадр остаётся верным).
* Часы в HUD обновляются с `aria-live="polite"`, но не чаще раза в минуту.
* Контраст текста HUD ≥ 4.5:1 на любом фоне (подложка при необходимости).
